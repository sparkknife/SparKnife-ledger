# انتشار نسخه در GitHub — گام به گام با تصویر ذهنی

شما نوشتید: «فقط نسخه درست کردم تو گیت، بعدشو نفهمیدم کجا چه کدی
وارد کنم.» این سند دقیقاً همان «بعدش» است.

**مهم:** در ۹۰٪ کارها **هیچ کدی وارد نمی‌کنید**. فقط کلیک می‌کنید و
فایل آپلود می‌کنید. کد فقط در گام ۱ و ۲ است، و آن هم کپی-پیست.

---

## قبل از شروع: بدانید چرا

وردپرس برای به‌روزرسانی خودکار دو چیز می‌خواهد:

1. بفهمد **نسخهٔ تازه‌ای هست** → از `release.json` می‌فهمد
2. **فایل زیپ** را دانلود کند → از GitHub Releases می‌گیرد

پس دو کار است: `release.json` را در مخزن بگذارید، و زیپ را در Releases.

**ترتیب مهم است:** اول Release بسازید، بعد `release.json` را push
کنید. اگر برعکس باشد، بین این دو لحظه وردپرس ۴۰۴ می‌گیرد.

---

# گام ۱ — نسخه را بسازید (خط فرمان)

پوشهٔ پروژه را در VS Code باز کنید. ترمینال را باز کنید
(`Ctrl+‌`` ` یا منوی Terminal → New Terminal) و بزنید:

```bash
bash tools/licensing/sparkknife.sh release --patch "رفع باگ نمایش مبلغ"
```

**این چه می‌کند:** نسخه را یکی بالا می‌برد (۱٫۲٫۰ → ۱٫۲٫۱)، زیپ
می‌سازد، و `release.json` را می‌نویسد.

**خروجی‌ای که می‌بینید:**

```
  ✓ نسخهٔ فعلی: 1.2.0
  ✓ نسخهٔ تازه: 1.2.1
  ✓ readme.txt هم‌گام شد
  ✓ زیپ ساخته شد
    /…/build/sparkknife-ledger-1.2.1.zip
  ✓ release.json به‌روز شد
```

**💡 نکته:** `--patch` یعنی ۱٫۲٫۰ → ۱٫۲٫۱ (رفع باگ).
`--minor` یعنی ۱٫۲٫۰ → ۱٫۳٫۰ (قابلیت تازه).
`--major` یعنی ۱٫۲٫۰ → ۲٫۰٫۰ (تغییر بزرگ).

از این به بعد **این نسخه را یادداشت کنید** — در گام ۳ لازمش دارید.
در مثال بالا: `1.2.1`

# گام ۲ — به گیت push کنید (خط فرمان)

در همان ترمینال، به‌ترتیب:

```bash
git add release.json sparkknife-ledger/
git commit -m "انتشار 1.2.1"
git push
```

**هر خط چه می‌کند:**

| خط | کار |
| --- | --- |
| `git add` | فایل‌های عوض‌شده را برای ثبت آماده می‌کند |
| `git commit` | ثبت می‌کند (متن داخل `"` را هرچه خواستید بنویسید) |
| `git push` | به GitHub می‌فرستد |

**⚠️ کلمهٔ `1.2.1` را با نسخهٔ خودتان عوض کنید** — همان که در گام ۱
چاپ شد.

**اگر Git گفت «author identity unknown»:** یعنی هنوز به گیت نگفته‌اید
شما کیستید. یک بار این دو خط را بزنید و بعد دوباره `git commit`:

```bash
git config --global user.name "SparKnife"
git config --global user.email "155084046+sparkknife@users.noreply.github.com"
```

# گام ۳ — Release در GitHub بسازید (کلیک فقط)

از اینجا به بعد **هیچ کدی وارد نمی‌کنید**.

### ۳.۱ — برو به صفحهٔ مخزن

مرورگر را باز کنید:

```
https://github.com/sparkknife/SparKnife-ledger
```

### ۳.۲ — Releases را باز کنید

در ستون **راست** صفحه، دنبال بخش **Releases** بگردید.
کنارش نوشته مثل `No releases published` یا تعداد release ها.

روی **Releases** کلیک کنید.

### ۳.۳ — Draft a new release

بالای صفحه یک دکمهٔ آبی هست: **Draft a new release**.
روی آن کلیک کنید.

### ۳.۴ — تگ را بزنید

فیلد **Choose a tag** را می‌بینید. داخلش تایپ کنید:

```
v1.2.1
```

⚠️ **حرف `v` را جا نیندازید** — و `1.2.1` را با نسخهٔ خودتان عوض کنید.

بعد از تایپ، یک گزینهٔ آبی زیرش ظاهر می‌شود:
`Create new tag: v1.2.1 on publish` — رویش کلیک کنید.

**اگر Target را می‌پرسد:** `main` را انتخاب کنید.

### ۳.۵ — عنوان

فیلد **Release title**:

```
v1.2.1
```

یا هرچه خواستید: `نسخهٔ ۱٫۲٫۱ — رفع باگ`.

### ۳.۶ — توضیحات (اختیاری)

کادر بزرگ **Describe this release** — می‌توانید خالی بگذارید یا
بنویسید چه عوض شده. این فقط برای نمایش است، وردپرس نمی‌خواندش.

### ۳.۷ — ⭐ زیپ را آپلود کنید (مهم‌ترین گام)

پایین صفحه، کادری هست:

```
Attach binaries by dropping them here or
selecting them to upload.
```

**روی همان متن کلیک کنید** (یا فایل را با موس بکشید و رها کنید).

پنجرهٔ انتخاب فایل باز می‌شود. بروید به:

```
پوشهٔ پروژه → build → sparkknife-ledger-1.2.1.zip
```

انتخابش کنید. آپلود شروع می‌شود (حدود ۱ مگابایت، چند ثانیه).

**⚠️ سه چیز که باید دقیقاً درست باشد:**

1. **فایل در پوشهٔ `build/` است** — نه هر جای دیگر
2. **نام فایل `sparkknife-ledger-1.2.1.zip` است** — دقیقاً همین، با همین
   خط تیره‌ها. اگر اسمش را عوض کنید، وردپرس پیدایش نمی‌کند.
3. **خود زیپ را آپلود کنید، نه پوشه را** — پوشه آپلود نمی‌شود، فقط
   فایل.

**اگر پوشهٔ `build` را نمی‌بینید:** در ویندوز، پوشه‌های مخفی ممکن است
پنهان باشند. یا در ترمینال بزنید:

```bash
ls build/
```

نام دقیق فایل را نشان می‌دهد.

### ۳.۸ — منتشر کنید

دکمهٔ سبز/آبی **Publish release** (یا `Publish release`) را بزنید.

# گام ۴ — بررسی کنید که کار کرد

### ۴.۱ — سایت خودتان را باز کنید

وارد پیشخوان وردپرس شوید. بروید به:

**پیشخوان → به‌روزرسانی‌ها**

باید ببینید:

```
افزونه‌ها
  ⬤ SparKnife Ledger
    نسخهٔ تازه‌ای موجود است — 1.2.1
    [جزئیات] [به‌روزرسانی الان]
```

**اگر ندیدید:** نگران نشوید، طبیعی است. وردپرس هر ۱۲ ساعت بررسی
می‌کند. برای فوری:

**پیشخوان → به‌روزرسانی‌ها → دکمهٔ «بررسی دوباره»** (بالای صفحه)

**اگر باز هم نبود:** یکی از این‌هاست:

| علت | چطور بفهمید |
| --- | --- |
| `release.json` push نشده | `https://github.com/sparkknife/SparKnife-ledger/blob/main/release.json` را باز کنید — باید نسخهٔ تازه را نشان دهد |
| نسخه در `release.json` بالا نرفته | همان صفحه، فیلد `version` |
| Release منتشر نشده | `https://github.com/sparkknife/SparKnife-ledger/releases` — باید `v1.2.1` را ببینید |
| نسخهٔ نصب‌شده همین است | `release.json` نسخه‌اش باید **بالاتر** از نصب‌شده باشد |

### ۴.۲ — یک بار دستی تست کنید

روی **«به‌روزرسانی الان»** بزنید.

وردپرس زیپ را دانلود می‌کند، پوشه را عوض می‌کند، و می‌گوید
«به‌روزرسانی موفق».

**حالا در پیشخوان → افزونه‌ها، باید نسخهٔ تازه را ببینید.**

# سؤال‌های رایج

### چرا نسخه دو جا نوشته می‌شود؟

سه جا، ولی ابزار خودش هم‌گام می‌کند:

| فایل | چه چیزی |
| --- | --- |
| `sparkknife-ledger/sparkknife-ledger.php` | `SPARKKNIFE_LEDGER_VERSION` — وردپرس از این می‌فهمد نصب‌شده چند است |
| `sparkknife-ledger/readme.txt` | `Stable tag` — برای نمایش |
| `release.json` | نسخهٔ منتشرشده — وردپرس از این می‌فهمد تازه چند است |

`release --patch` هر سه را خودش عوض می‌کند. دستی دست نزنید.

### اگر نسخه را اشتباه بالا بردم؟

اشکالی ندارد. دوباره `release --patch` بزنید؛ دو پله می‌رود
(۱٫۲٫۰ → ۱٫۲٫۲). نسخهٔ پرش‌شده مشکلی ندارد.

### اگر زیپ را اشتباه آپلود کردم؟

در صفحهٔ Release، روی **Edit** بزنید (مداد کنار عنوان). فایل را حذف
کنید و درست را آپلود کنید. Release را دوباره منتشر کنید.

### آیا مشتری‌ها خودشان به‌روزرسانی می‌کنند؟

خودکار **نمی‌شود**. وردپرس وقتی به‌روزرسانی‌های خودکار افزونه‌ها
روشن باشد، آن را انجام می‌دهد — و آن تنظیم پیش‌فرض خاموش است.
مشتری یک کلیک می‌زند. این عمدی است: به‌روزرسانی خودکار بدون کنترل،
اگر نسخه‌ای باگ داشته باشد، همه را هم‌زمان خراب می‌کند.

### اگر مشتری نسخهٔ قدیمی داشته باشد و به‌روزرسانی نکند؟

کار می‌کند. ولی باگ‌های رفع‌شده را هم دارد. در متن صفحهٔ محصول
بنویسید که به‌روز نگه داشتن توصیه می‌شود.
