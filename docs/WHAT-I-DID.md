## ۱. جفت کلید لایسنس — **انجام شد**

این گام ۰ فهرست قبلی شما بود و بزرگ‌ترین مانع فروش. حالا:

```
tools/licensing/private_key.pem     ← کلید خصوصی (در .gitignore، در بسته نیست)
tools/licensing/public_key.pem      ← کلید عمومی
PUBLIC_KEY در کد                   ← همان کلید عمومی، جایگزین شد
```

اثر انگشت کلید (SHA-256): `96e14f37a0b6d2ce676cc09ec4b15397aea7e66ed4d730d5deab2d95ee05cfbb`

### ⚠️ این کلید پاک شد

کلید خصوصی **با بازنشانی محیط توسعه پاک شد** و در این نسخه وجود
ندارد. `PUBLIC_KEY` داخل کد هنوز کلید عمومی قدیمی است.

یعنی **زیپ فعلی نمی‌تواند لایسنس صادر کند.** باید جفت تازه بسازید و
`PUBLIC_KEY` را جایگزین کنید — دستورهای آماده در
[`FROM-ZIP-TO-LIVE.md`](FROM-ZIP-TO-LIVE.md) گام ۱.

درس این اتفاق: کلید خصوصی نباید هرگز فقط در یک محیط موقت باشد.
اولین کاری که پس از ساختش بکنید، پشتیبان‌گیری است.

```bash
# همین حالا، پیش از هر کار دیگری:
cat tools/licensing/private_key.pem
```

خروجی را در گاوصندوق رمز (1Password / Bitwarden) و یک نسخهٔ آفلاین
روی USB بگذارید. **این تنها کار باقی‌ماندهٔ حیاتی است.**

## ۲. صدور و آزمون لایسنس — **انجام شد**

اولین بار در تاریخ پروژه، یک لایسنس واقعی صادر و در افزونه آزموده شد:

| آزمون | نتیجه |
| --- | --- |
| کلید معتبر برای دامنهٔ درست | `valid=true`, `edition=pro` ✓ |
| کلید دست‌کاری‌شده (محتوای عوض، امضای اصلی) | رد شد ✓ |
| کلید معتبر برای دامنهٔ دیگر | رد شد ✓ |

یعنی سیستم امضا واقعاً کار می‌کند، نه فقط از نظر نحوی درست است.

### تأیید خودتان

```bash
php tools/licensing/issue.php --domain=yourdomain.com --edition=pro --expiry=2027-12-31
```

کلید `SPK1.xxx.yyy` را در پنل → لایسنس وارد کنید. باید `pro` شود.
