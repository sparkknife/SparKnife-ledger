## ⚠️ اول: کدام فایل را دانلود کنید

این بخش را رد نکنید. اگر اشتباه دانلود کنید، **هیچ دستوری کار
نمی‌کند** و پیام خطا هم نمی‌گوید چرا.

### ❌ اشتباه رایج

صفحهٔ اصلی مخزن در GitHub یک دکمهٔ سبز **Code** دارد. اگر روی آن بزنید
و **Download ZIP** را انتخاب کنید، بسته به شاخهٔ پیش‌فرض، ممکن است
فایلی بگیرید که فقط یک README دارد.

**علامت اشتباه بودن:** وقتی زیپ را باز می‌کنید، هیچ‌کدام از این‌ها
نیست:

```
tools/
sparkknife-ledger/
docs/
```

فقط `README.md` هست و شاید `.gitignore`.

### ✅ راه درست

زیپ باید از شاخهٔ `main` گرفته شود **پس از merge شدن کار**. اگر مطمئن
نیستید، این را بررسی کنید:

```bash
# پس از استخراج، داخل پوشه بزنید:
ls
```

باید اینها را ببینید:

```
AUTHORS  LICENSE  NOTICE  README.md
docs  package.json  sparkknife-ledger  tests  tools
```

اگر فقط `README.md` دیدید، زیپ اشتباه است. **دانلود دوباره:**

```
https://codeload.github.com/sparkknife/SparKnife-ledger/zip/refs/heads/main
```

یا با ترمینال VS Code:

```bash
cd ~/Desktop
curl -L -o spk.zip "https://codeload.github.com/sparkknife/SparKnife-ledger/zip/refs/heads/main"
unzip spk.zip
cd SparKnife-ledger-main

```

## گام ۰ — باز کردن پوشه در VS Code

این را یک بار انجام دهید:

۱. VS Code را باز کنید
۲. منوی بالا → **File** → **Open Folder...**
۳. پوشه‌ای که `tools` و `sparkknife-ledger` داخلش است را انتخاب کنید
۴. منوی بالا → **Terminal** → **New Terminal**

پایین پنجره یک کادر باز می‌شود. **همهٔ دستورهای این سند را همان‌جا
بزنید.**

| سیستم | میانبر باز کردن ترمینال |
| --- | --- |
| ویندوز / لینوکس | `` Ctrl + ` `` |
| مک | `` Cmd + ` `` |

### اگر روی ویندوز هستید — یک بار این را بررسی کنید

در همان ترمینال بزنید:

```
echo $SHELL
```

اگر `bash` نشان داد → خوب است.

اگر خطا داد یا `powershell` بود: کنار کادر ترمینال فلش `v` را
بزنید → **Select Default Profile** → **Git Bash**.

اگر Git Bash نبود، [Git for Windows](https://git-scm.com/download/win)
را نصب کنید و VS Code را ببندید و دوباره باز کنید.

تقریباً همیشه یعنی از پوشهٔ اشتباه اجرا کرده‌اید یا زیپ اشتباه است.

| دستوری که زدید | خطا | یعنی |
| --- | --- | --- |
| `php tools/licensing/make-keys.php` | `Could not open input file` | در پوشهٔ درست نیستید |
| `ls tools` | `No such file or directory` | زیپ اشتباه است |
| `ls` | فقط `README.md` | زیپ اشتباه است |

**راه‌حل قطعی:** در ترمینال VS Code بزنید:

```bash
pwd
```

خروجی باید مسیری باشد که **داخلش** `tools` و `sparkknife-ledger` هست.
اگر نبود:

```bash
ls ..
```

ببینید پوشهٔ `SparKnife-ledger-main` کجاست و با `cd` به آن بروید:

```bash
cd ~/Desktop/SparKnife-ledger-main     # مسیر خودتان

```

**نکتهٔ مهم:** در VS Code، ترمینال خودش را در پوشه‌ای باز می‌کند که
با **File → Open Folder** باز کرده‌اید. اگر ریشهٔ زیپ را باز نکرده
باشید، همهٔ دستورها از جای اشتباه اجرا می‌شوند.

## گام ۱ — بررسی PHP (۱ دقیقه)

در ترمینال بزنید:

```
php -v
```

### اگر نسخه نشان داد

چیزی مثل `PHP 8.2.12 (cli)` می‌بینید. **برو گام ۲.**

### اگر `php: command not found` داد

**ویندوز:**

۱. [windows.php.net/download](https://windows.php.net/download) را باز کنید
۲. زیر **PHP 8.2** روی **Thread Safe** → **x64** بزنید و zip را بگیرید
۳. آن را در `C:\php` باز کنید
۴. کلید `Win` را بزنید، تایپ کنید `environment`، و
   **Edit the system environment variables** را باز کنید
۵. دکمهٔ **Environment Variables...**
۶. در جدول پایینی (**System variables**) روی `Path` دوبار کلیک کنید
۷. **New** → بنویسید `C:\php` → OK در همهٔ پنجره‌ها
۸. **VS Code را کامل ببندید و دوباره باز کنید** ← این را رد نکنید
۹. دوباره `php -v`

**مک:**

```
brew install php
```

**اوبونتو / دبیان:**

```
sudo apt install php-cli
```

## گام ۲ — ساخت کلید با یک دستور (۳ دقیقه)

از ریشهٔ زیپ، در ترمینال VS Code:

```
php tools/licensing/make-keys.php
```

**همین. یک دستور.**

این اسکریپت خودش:

- جفت کلید ۳۰۷۲ بیتی می‌سازد
- `PUBLIC_KEY` داخل کد را جایگزین می‌کند
- با یک امضای آزمایشی **تأیید می‌کند** که کلیدها جفت‌اند
- کلید خصوصی را چاپ می‌کند تا پشتیبان بگیرید

### خروجی موفق

```
ساخت جفت کلید SparKnife Ledger
──────────────────────────────────────────────────

✓ افزونهٔ OpenSSL در PHP فعال است
→ ساخت کلید ۳۰۷۲ بیتی (چند ثانیه طول می‌کشد) … ✓
✓ کلید خصوصی  → tools/licensing/private_key.pem
✓ کلید عمومی  → tools/licensing/public_key.pem

اثر انگشت (SHA-256):
  cde6cc2b09e7b0fe80925eabd59b2814ebdfa5ed405b6bb63a27ddf1339a23d8

──────────────────────────────────────────────────
→ جایگزینی PUBLIC_KEY در کد …
✓ PUBLIC_KEY جایگزین شد
✓ تأیید: امضای آزمایشی با کلید داخل کد بررسی شد و معتبر بود

──────────────────────────────────────────────────

⚠️  همین حالا پشتیبان بگیرید

   محتوای کلید خصوصی:

-----BEGIN PRIVATE KEY-----
MIIG/gIBADANBgkqhkiG9w0BAQEFAASCBugwggbkAgEAAoIBgQC0WKkgxmu9wpDo
...
-----END PRIVATE KEY-----
```

### ۲.۱ پشتیبان — همین حالا

متن `-----BEGIN PRIVATE KEY-----` تا `-----END PRIVATE KEY-----` را
**کامل** کپی کنید و در دو جا بگذارید:

- [ ] گاوصندوق رمز (1Password / Bitwarden)
- [ ] یک USB یا پرینت در جای امن

اگر این گم شود، همهٔ لایسنس‌های فروخته‌شده باطل می‌شوند.

### اگر خطا داد

| خطا | کار |
| --- | --- |
| `افزونهٔ OpenSSL در PHP فعال نیست` | در `php.ini` خط `extension=openssl` را از حالت توضیح خارج کنید. مسیر فایل: `php --ini` |
| `کلید خصوصی از قبل وجود دارد` | کلید قبلی هست. اگر مطمئنید، `بله` بنویسید و Enter |
| `فایل افزونه پیدا نشد` | از ریشهٔ زیپ اجرا نکردید. `ls` بزنید — باید `tools` و `sparkknife-ledger` را ببینید |
| `خروجی کلید خصوصی خالی است` | نصب PHP ناقص است. PHP را دوباره نصب کنید |

> **نکته:** این اسکریپت را خودم روی PHP 8.2 اجرا و تأیید کردم —
> کلید ساخت، `PUBLIC_KEY` جایگزین شد، و لایسنس ساخته‌شده با آن
> `openssl_verify = 1` (معتبر) داد.

### چرا نه با `openssl` سیستم؟

اگر `openssl` دارید، همان سه دستور کلاسیک هم کار می‌کند. ولی برای
جایگزینی `PUBLIC_KEY` باید دستی فایل را ویرایش کنید — و همان‌جاست
که اشتباه پیش می‌آید. `make-keys.php` هر دو کار را با هم و با
تأیید انجام می‌دهد.

## گام ۴ — بستهٔ تازه بسازید (۲ دقیقه)

چون `PUBLIC_KEY` را عوض کردید، زیپ قبلی دیگر درست نیست. زیپ تازه بسازید:

**لینوکس / مک:**

```bash
# از ریشهٔ زیپ
rm -f sparkknife-ledger.zip
zip -qr sparkknife-ledger.zip sparkknife-ledger -x "*.git*" "*.DS_Store"
```

**ویندوز (PowerShell):**

```powershell
Compress-Archive -Path sparkknife-ledger -DestinationPath sparkknife-ledger.zip -Force
```

### تأیید بسته

```bash
# تعداد فایل — باید ۸۳ باشد
unzip -l sparkknife-ledger.zip | tail -1

# کلید خصوصی نباید داخلش باشد — باید 0 باشد
unzip -l sparkknife-ledger.zip | grep -c "private_key"
```

⚠️ اگر عدد دوم ۱ یا بیشتر بود، **متوقف شوید**. کلید خصوصی هرگز نباید
در بسته‌ای باشد که به دست مشتری می‌رسد.

### امضا (اختیاری ولی توصیه‌شده)

```bash
./tools/sign-release.sh sparkknife-ledger.zip
./tools/verify-release.sh sparkknife-ledger.zip tools/licensing/public_key.pem
```

باید بگوید `نتیجه: بسته معتبر است ✓`.

## گام ۶ — بررسی سلامت (۵ دقیقه)

### ۵.۱ روشن کردن نمایش خطا (اگر مشکلی هست)

در `wp-config.php`، پیش از خط `/* That's all, stop editing! */`:

```php
define( 'WP_DEBUG', true );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEBUG_DISPLAY', false );
```

خطاها در `wp-content/debug.log` نوشته می‌شوند.

**پس از رفع مشکل، `WP_DEBUG` را به `false` برگردانید.**

### ۵.۲ صفحهٔ سلامت

**دفتر حساب → سلامت و امنیت**

انتظار: **۷ بررسی**. سه مورد ممکن است هشدار بدهند:

| بررسی | چرا | کار |
| --- | --- | --- |
| HTTPS | اگر سایت HTTP است | **حتماً رفع کنید** |
| پیشوند جدول | اگر `wp_` است | بی‌خطر |
| لایسنس | تا کلیدی وارد نکنید | طبیعی |

### ۵.۳ فعال‌سازی لایسنس

**دفتر حساب → لایسنس**

کلیدی که در گام ۳.۱ ساختید را وارد کنید — ولی باید برای **دامنهٔ همین
سایت** باشد، نه `example.com`.

```bash
# کلید درست برای دامنهٔ سایت خودتان
php tools/licensing/issue.php --domain=دامنه-سایت-شما.com --edition=pro --expiry=2027-12-31
```

انتظار: نسخه از `free` به `pro` تغییر کند.

### ۵.۴ اجرای سوئیت آزمون (اختیاری ولی ارزشمند)

```bash
php tests/run-tests.php /مسیر/به/wp-load.php
```

مثال واقعی:

```bash
php tests/run-tests.php /var/www/html/wp-load.php
```

انتظار در پایان:

```
همه تست‌ها موفق: ۹۹۰ مورد
```

⚠️ **روی سایت تولیدی اجرا نکنید.** آزمون داده می‌سازد و پاک می‌کند.

## ضمیمهٔ الف — دستورهای تک‌خطی برای کپی

اینها را پشت سر هم بزنید اگر عجله دارید. **قبل از اجرا، گام ۱.۴ را
بخوانید** تا بدانید چه می‌کنید.

```bash
# از ریشهٔ زیپ
cd tools/licensing
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out private_key.pem
openssl rsa -in private_key.pem -pubout -out public_key.pem
openssl pkey -in private_key.pem -noout -check
cd ../..

# جایگزینی کلید
php -r '
$f = "sparkknife-ledger/includes/Core/class-sparkknife-ledger-license.php";
$pem = trim(file_get_contents("tools/licensing/public_key.pem"));
$src = file_get_contents($f);
$new = preg_replace("/const PUBLIC_KEY = \x27.*?\x27;/s", "const PUBLIC_KEY = \x27" . $pem . "\x27;", $src, 1);
file_put_contents($f, $new);
echo "کلید جایگزین شد\n";
'

# بستهٔ تازه
rm -f sparkknife-ledger.zip
zip -qr sparkknife-ledger.zip sparkknife-ledger -x "*.git*"
```

بعد `sparkknife-ledger.zip` را در وردپرس آپلود کنید.
