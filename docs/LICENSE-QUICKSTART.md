# از صفر تا لایسنس — سه دستور

این سند فقط سه دستور دارد. هر سه در **Git Bash** (همان ترمینالی که در
VS Code باز می‌کنید) اجرا می‌شوند. به PHP نیازی نیست.

---

## یک بار: راه‌اندازی کلید

```bash
bash tools/licensing/sparkknife.sh setup
```

چه می‌کند:

- کلید خصوصی ۳۰۷۲-بیتی می‌سازد → `tools/licensing/private_key.pem`
- کلید عمومی را از آن استخراج می‌کند → `tools/licensing/public_key.pem`
- **کلید عمومی را داخل کد می‌گذارد** → `class-sparkknife-ledger-license.php`
- جفت بودنشان را با امضا و تأیید واقعی می‌آزماید
- اثر انگشت را چاپ می‌کند تا بعداً بشناسیدش

اگر کلید از قبل باشد، دوباره نمی‌سازد. برای ساخت تازه: `setup --force`
(⚠️ با کلید تازه، همهٔ لایسنس‌های قبلی باطل می‌شوند).

### ⚠️ کلید خصوصی

`private_key.pem` هرگز نباید در گیت، در زیپ، یا در چت باشد. با آن هر
لایسنس جعلی قابل ساخت است. جایش: مدیر رمز یا پشتیبان رمزگذاری‌شده.

اگر گم شود، دیگر نمی‌توانید لایسنس تازه برای مشتری‌های فعلی صادر کنید
(لایسنس‌های صادرشده کار می‌کنند، ولی تمدید ممکن نیست).

## برای هر مشتری: صدور لایسنس

```bash
bash tools/licensing/sparkknife.sh key --domain=example.com
```

اگر `--domain` ندهید، می‌پرسد. بهترین کار: دامنه را از خود مشتری بپرسید
و همان را وارد کنید.

خروجی یک رشتهٔ `SPK1....` است. همان را به مشتری بدهید.

### گزینه‌ها

| گزینه | کار |
| --- | --- |
| `--domain=example.com` | یک سایت |
| `--domain="*.example.com"` | همهٔ زیردامنه‌های مشتری |
| `--domain="*"` | هر دامنه‌ای (فروش دائمی) |
| `--edition=pro` | پیش‌فرض |
| `--edition=agency` | برای کل شبکه |
| `--expiry=2028-06-01` | تاریخ انقضای دلخواه |
| `--forever` | بدون انقضا |
| `--quiet` | فقط خود کلید، بدون توضیح (برای اسکریپت) |

اگر `--expiry` ندهید، **یک سال بعد** می‌گذارد.

### بررسی یک کلید موجود

```bash
bash tools/licensing/sparkknife.sh key --verify=SPK1.xxx.yyy
```

می‌گوید امضا معتبر است یا نه، برای چه دامنه‌ای، تا کِی، و منقضی شده یا نه.

## برای انتشار: ساخت زیپ

```bash
bash tools/licensing/sparkknife.sh pack
```

زیپ را در `build/sparkknife-ledger-1.1.0.zip` می‌سازد و **قبل از تحویل
بررسی می‌کند**:

- ✓ هیچ فایل کلیدی داخل بسته نباشد
- ✓ نام پوشهٔ داخل زیپ `sparkknife-ledger` باشد (وردپرس همین را می‌خواهد)
- ✓ ساختار `sparkknife-ledger/sparkknife-ledger.php` درست باشد

بعد از ساخت هم دوباره زیپ را باز می‌کند و می‌بیند کلید خصوصی داخلش نباشد.
اگر باشد، هشدار می‌دهد و متوقف می‌شود.

همین زیپ را در وردپرس نصب می‌کنید:
**پیشخوان → افزونه‌ها → افزودن → بارگذاری افزونه → انتخاب زیپ → نصب**

## وضعیت: هر وقت خواستید ببینید کجایید

```bash
bash tools/licensing/sparkknife.sh status
```

می‌گوید کلید خصوصی هست یا نه، کلید کد با کلید دیسک هم‌تراز است یا نه،
و نسخهٔ افزونه چند است.

---

## مشتری چطور فعال می‌کند

1. وارد پیشخوان وردپرس شود
2. **SparKnife Ledger → سلامت و امنیت**
3. بخش «لایسنس» → کادر متن → کلید را بچسباند
4. **فعال‌سازی لایسنس**

صفحه بعد می‌گوید:

```
لایسنس فعال است.
نسخه:   pro
دامنه:  example.com
انقضا:  2028-06-01
سریال:  1CFD9C1D
```

### اگر رد شد

| پیام | معنی |
| --- | --- |
| «شکل کلید درست نیست» | کپی ناقص شده — دوباره کامل بفرستید |
| «امضای لایسنس معتبر نیست» | کلید دستکاری شده یا مال افزونهٔ دیگری است |
| «برای دامنهٔ … صادر شده» | کلید برای سایت دیگری است — کلید تازه بگیرید |
| «لایسنس منقضی شده» | تاریخ گذشته — با `--expiry` تازه صادر کنید |
| «کلید عمومی افزونه بارگذاری نشد» | نصب ناقص — زیپ را دوباره نصب کنید |

## دامنه چطور تطبیق داده می‌شود

| کلید برای | روی این سایت کار می‌کند |
| --- | --- |
| `example.com` | `example.com` و `www.example.com` ✓ |
| `example.com` | `shop.example.com` ✗ |
| `*.example.com` | `example.com`، `www.example.com`، `shop.example.com` ✓ |
| `*` | هر جایی ✓ |

اگر مشتری سایتش را جابه‌جا کند (مثلاً از `old.com` به `new.com`)، کلید
قبلی کار نمی‌کند. باید کلید تازه صادر کنید.

## چرا آفلاین است

بررسی لایسنس **هیچ تماس شبکه‌ای ندارد**. امضا با کلید عمومیِ داخل کد
بررسی می‌شود.

این یعنی:

- ✓ روی سرور بدون اینترنت کار می‌کند
- ✓ اگر سایت ما روزی خاموش شود، لایسنس مشتری‌ها کار می‌کند
- ✓ هیچ داده‌ای از مشتری به ما نمی‌رود
- ✗ نمی‌توانیم لایسنس را از راه دور باطل کنیم

آن آخری برای فروش یک‌باره مشکلی نیست. اگر روزی مدل اشتراکی خواستید،
یک بررسی اختیاری با سرور اضافه می‌شود که فقط وقتی اینترنت هست اجرا شود.

## دو نکتهٔ فنی که باید بدانید

### ۱) `\n` در PHP

اگر روزی کلید عمومی را دستی در کد بگذارید، حواستان باشد:

```php
const PUBLIC_KEY = '-----BEGIN\nMIIB...';   // ✗ غلط
const PUBLIC_KEY = "-----BEGIN\nMIIB...";   // ✓ درست
```

تک‌کوتیشن در PHP تفسیر نمی‌کند، پس `\n` همان دو کاراکتر می‌ماند و PEM
نامعتبر می‌شود. کلاس لایسنس حالا خودش این را اصلاح می‌کند، ولی بهتر است
از اول درست باشد.

### ۲) تفاوت free و pro

در نسخهٔ فعلی، **نسخهٔ رایگان و pro از نظر عملکرد یکسان‌اند**. لایسنس
صادر می‌شود و در صفحه دیده می‌شود، ولی هیچ قابلیتی را باز نمی‌کند.

جزئیات و سه انتخاب برای اینکه این را واقعی کنید: `docs/HOW-LICENSE-WORKS.md`
