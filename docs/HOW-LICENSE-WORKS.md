# سیستم لایسنس چطور کار می‌کند

سندی برای شما (فروشنده)، نه خریدار. اینجا نوشته‌ام دقیقاً چه چیزی
کار می‌کند، چه چیزی کار نمی‌کند، و چه تصمیمی باید بگیرید.

---

## بخش ۱ — چطور کار می‌کند (فنی)

### کلیدها

| فایل | کجاست | چه کاری می‌کند |
| --- | --- | --- |
| `private_key.pem` | روی دستگاه شما، در گاوصندوق | لایسنس را **امضا** می‌کند |
| `public_key.pem` | داخل کد افزونه | امضا را **بررسی** می‌کند |

کلید خصوصی **هیچ‌وقت** به دست مشتری نمی‌رسد. حتی اگر کسی کد افزونه
را کامل بخواند، نمی‌تواند لایسنس جعل کند.

### قالب کلید لایسنس

```
SPK1.<payload>.<signature>
```

- `SPK1` — پیشوند نسخه
- `payload` — متن ساده، base64url شده: `دامنه|انقضا|نسخه|سریال`
  - مثال: `example.com|2027-12-31|pro|A1B2C3D4`
- `signature` — امضای RSA-SHA256 آن متن

### وقتی مشتری کلید را وارد می‌کند

افزونه چهار چیز را بررسی می‌کند، **به‌ترتیب**:

| # | بررسی | اگر رد شد |
| --- | --- | --- |
| ۱ | قالب `SPK1.xxx.yyy` درست است؟ | «شکل کلید درست نیست» |
| ۲ | امضا با کلید عمومی می‌خواند؟ | «امضای لایسنس معتبر نیست» |
| ۳ | نسخه `pro` یا `agency` است؟ | «نسخهٔ لایسنس شناخته نشد» |
| ۴ | دامنهٔ سایت با دامنهٔ کلید می‌خواند؟ | «برای دامنهٔ … صادر شده» |
| ۵ | منقضی نشده؟ | «لایسنس منقضی شده» |

**هیچ تماس شبکه‌ای وجود ندارد.** بررسی کاملاً آفلاین است. اگر سایت
مشتری اینترنت نداشته باشد، لایسنس باز هم کار می‌کند.

### دامنه چطور تطبیق داده می‌شود

| کلید برای | روی این سایت کار می‌کند |
| --- | --- |
| `example.com` | `example.com` و `www.example.com` ✓ |
| `example.com` | `shop.example.com` ✗ |
| `*.example.com` | `example.com`، `www.example.com`، `shop.example.com` ✓ |
| `*` | هر دامنه‌ای ✓ |

### کجا وارد می‌شود

افزونه → **سلامت و امنیت** → بخش «لایسنس» → کادر متن → **فعال‌سازی لایسنس**

### چطور صادر می‌کنید

```bash
# یک سایت
bash tools/licensing/issue.sh --domain=example.com --edition=pro --expiry=2027-12-31

# کل شبکهٔ مشتری
bash tools/licensing/issue.sh --domain="*.example.com" --edition=agency --expiry=2027-12-31

# بدون انقضا (فروش دائمی)
bash tools/licensing/issue.sh --domain=example.com --edition=pro

# بررسی یک کلید
bash tools/licensing/issue.sh --verify=SPK1.xxx.yyy
```

خروجی یک رشتهٔ `SPK1....` است. آن را به مشتری بدهید.

## بخش ۲ — ⚠️ چیزی که باید بدانید

### نسخهٔ free و pro در حال حاضر **هیچ تفاوت عملکردی ندارند**

این را با جستجوی کامل کد تأیید کردم:

```
grep -rn "edition()" sparkknife-ledger/
→ فقط یک جا: ثبت در لاگ امنیتی
```

یعنی:

| | نسخهٔ free | نسخهٔ pro |
| --- | --- | --- |
| همهٔ قابلیت‌ها | ✓ دارد | ✓ دارد |
| تعداد شخص | نامحدود | نامحدود |
| خروجی CSV | ✓ | ✓ |
| گزارش‌ها | ✓ | ✓ |

**لایسنس فقط یک برچسب است.** کسی که کلید نداشته باشد، هیچ چیزی را
از دست نمی‌دهد.

### این برای فروش چه معنایی دارد

اگر امروز افزونه را بفروشید:

- مشتری می‌تواند بدون هیچ کلیدی از همهٔ قابلیت‌ها استفاده کند
- هیچ دلیلی ندارد پول بدهد
- لایسنس فقط «اعلام وفاداری» است

**این عمداً این‌طور ساخته نشده** — فقط هنوز پیاده‌سازی نشده. سیستم
امضا کامل و امن است؛ چیزی که نیست، **قابلیت وابسته به لایسنس** است.

## بخش ۳ — سه انتخاب شما

### انتخاب ۱ — برای الان کافی است (ساده‌ترین)

افزونه را **رایگان با لایسنس دوگانه** عرضه کنید:

- GPL برای استفادهٔ آزاد
- لایسنس تجاری برای کسی که نمی‌خواهد کد بازنشر شود

**درآمد از راه پشتیبانی و سفارشی‌سازی**، نه از فروش کلید.

لایسنس RSA را نگه دارید — برای آینده آماده است، و مشتری‌هایی که
لایسنس تجاری می‌گیرند، کلید معتبر می‌گیرند و در صفحه می‌بینند.

**وقت لازم:** صفر. همین حالا قابل انتشار است.

### انتخاب ۲ — یک قابلیت pro واقعی اضافه کنید

پیشنهاد من: **تعداد اشخاص** یا **خروجی اکسل**.

محدودیت در `Person_Service::create()` گذاشته می‌شود:

```php
if ( ! Sparkknife_Ledger_License::is_active() ) {
    $count = Sparkknife_Ledger_Person_Repository::instance()->count_all();

    if ( $count >= 50 ) {
        return new WP_Error(
            'sparkknife_ledger_limit',
            __( 'نسخهٔ رایگان تا ۵۰ شخص. برای نامحدود، لایسنس تهیه کنید.', 'sparkknife-ledger' )
        );
    }
}
```

**وقت لازم:** ۲ ساعت کار من + تست.

**هزینه:** باید در مستندات و صفحهٔ فروش شفاف بگویید که نسخهٔ رایگان
۵۰ شخص دارد.

### انتخاب ۳ — هر دو

لایسنس را برای «نسخهٔ تجاری» داشته باشید (بدون محدودیت عملکردی)، **و**
یک قابلیت راحت اضافه کنید که فقط pro داشته باشد — مثلاً «خروجی اکسل
با قالب» یا «گزارش چند-شخصی».

## بخش ۴ — چه چیزی امن است و چه چیزی نه

### امن است ✓

| مورد | آزمایش |
| --- | --- |
| جعل کلید بدون کلید خصوصی | ناممکن (RSA-3072) |
| دستکاری payload | رد می‌شود |
| دستکاری امضا | رد می‌شود |
| استفادهٔ کلید روی دامنهٔ دیگر | رد می‌شود |
| لایسنس منقضی | رد می‌شود |
| تماس شبکه‌ای | ندارد — کار روی سرور بدون اینترنت |

### امن نیست ✗

| مورد | چرا | چطور جلویش را بگیرید |
| --- | --- | --- |
| کسی کد PHP را عوض کند و بررسی لایسنس را بردارد | کد روی سرور مشتری است | GPL اجازه می‌دهد؛ کسی که این کار را بکند، مشتری نیست |
| کسی `public_key.pem` را عوض کند | اگر کد را عوض کند، بله | رمز کردن کد — ولی ارزشش را ندارد |

**واقعیت:** هر افزونهٔ وردپرسی که لایسنس آفلاین دارد، همین وضع را
دارد. کسی که می‌خواهد کلید را بشکند، باید کد PHP را ویرایش کند —
و آن آدم مشتری شما نیست.

---

## بخش ۵ — خلاصهٔ یک‌پاراگرافی

> سیستم لایسنس **کامل و امن** است: RSA-3072، بررسی آفلاین، تطبیق دامنه،
> انقضا. مشتری کلید را در صفحهٔ سلامت وارد می‌کند و صفحه می‌گوید نسخه
> `pro` است. **ولی** در این نسخه، `free` و `pro` عملکرد یکسان دارند —
> لایسنس فقط برچسب است. اگر می‌خواهید واقعاً بفروشید، باید یک محدودیت
> در نسخهٔ رایگان بگذارید (انتخاب ۲) یا مدل درآمد را پشتیبانی قرار دهید
> (انتخاب ۱).
