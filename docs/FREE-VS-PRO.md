# نسخهٔ نصب‌شدهٔ شما با نسخهٔ لایسنس‌دار چه فرقی دارد؟

**جواب کوتاه: در عملکرد، هیچ.**

---

## با چشم خودتان ببینید

| | کلید ندارید | کلید `pro` دارید |
| --- | --- | --- |

| افزودن تراکنش | ✓ | ✓ |
| گزارش فردی | ✓ | ✓ |

هیچ سقفی، هیچ قفل، هیچ بخش خاکستری.

---

## پس کلید چه می‌کند؟

فقط یک چیز: صفحهٔ «سلامت و امنیت» عوض می‌شود.

**بدون کلید:**

> ⚠️ لایسنس فعال نیست. نسخهٔ رایگان.
> [کادر متن] [فعال‌سازی لایسنس]

**با کلید `pro`:**

> ✓ لایسنس فعال است.
> نسخه: `pro` · دامنه: `example.com` · انقضا: `2028-06-01` · سریال: `A1B2C3D4`
> [حذف لایسنس از این سایت]

**همین.** چهار خط اطلاعات بیشتر، و هیچ قابلیت بیشتری.

---

## چرا این‌طور است

این باگ نیست. سیستم امضا کامل و امن است — با کلید جعلی، با payload
دستکاری‌شده، و روی دامنهٔ غلط آزموده و رد شد.

چیزی که نیست، **قابلیت وابسته به لایسنس** است. کد هیچ‌جا از
`is_active()` استفاده نمی‌کند تا قابلیتی را باز یا بسته کند:

```bash
grep -rn "is_active()" sparkknife-ledger/
# فقط تعریف خودش. هیچ استفاده‌ای.
```

## اگر امروز بفروشید چه می‌شود

مشتری می‌گیرد، نصب می‌کند، و **همه‌چیز را بدون کلید دارد**.

- دلیلی ندارد پول بدهد
- اگر بدهد، از لطف است نه از نیاز
- نمی‌تواند به کسی توضیح بدهد چرا پول داده

## سه راه پیش رو

### راه ۱ — رایگان بدهید، از جای دیگر درآمد بگیرید

افزونه رایگان با لایسنس دوگانه (GPL یا تجاری).

**درآمد:** پشتیبانی، سفارشی‌سازی، نصب و راه‌اندازی.

**مزیت:** همین حالا آماده است. هیچ تغییر کدی لازم نیست.

**عیب:** فروش کلید معنا ندارد.

---

### راه ۲ — یک محدودیت واقعی بگذارید

پیشنهاد من: **۵۰ شخص در نسخهٔ رایگان.**

کدش این است، در `Person_Service::create()`:

```php
if ( ! Sparkknife_Ledger_License::is_active() ) {
    $count = Sparkknife_Ledger_Person_Repository::instance()->count_by_status( 'all' );

    if ( $count >= 50 ) {
        return new WP_Error(
            'sparkknife_ledger_limit',
            __( 'نسخهٔ رایگان تا ۵۰ شخص. برای نامحدود، لایسنس تهیه کنید.', 'sparkknife-ledger' )
        );
    }
}
```

**مزیت:** مدل فروش روشن و قابل توضیح.

**عیب:** باید در همه‌جا شفاف بگویید. کاربری که ۴۹ شخص دارد و ۵۰-ام
را نمی‌تواند اضافه کند، عصبانی می‌شود اگر از قبل نداند.

**وقت:** ۲ ساعت کار من + تست.

---

### راه ۳ — قابلیت راحت را پولی کنید

محدودیت نگذارید — یک قابلیت **خوب** را فقط برای pro بگذارید.

پیشنهادها به‌ترتیب ارزش:

| قابلیت | چرا خوب است |
| --- | --- |
| خروجی اکسل با قالب | اکسل چیزی است که همه می‌خواهند و CSV جایگزینش نیست |
| گزارش چند-شخصی | برای کسی که چند حساب دارد |
| یادآوری خودکار بدهی | ایمیل/پیامک به بدهکار — کار واقعی می‌کند |
| چند-کاربری با دسترسی محدود | برای دفتر با منشی |

**مزیت:** کاربر رایگان چیزی را از دست نمی‌دهد. فقط چیزی را که ندارد
می‌خرد. رضایت بیشتری دارد.

**عیب:** کار بیشتری می‌برد از یک `if`.

---

## پیشنهاد من

**راه ۳، با «خروجی اکسل» شروع کنید.**

دلیل:

1. کاربر رایگان هیچ چیز را از دست نمی‌دهد → بدنامی ندارد
2. CSV دارید، پس ساختار داده آماده است → کار کم
3. اکسل واقعاً چیزی است که کاربر پول برایش می‌دهد
4. می‌توانید بعداً قابلیت‌های دیگر اضافه کنید، بدون اینکه کاربر
   رایگان احساس تنبیه کند

---

## هر تصمیمی گرفتید، مهم است که این را بدانید

لایسنس فعلی **امن و درست** است. اگر فردا محدودیت اضافه کنید، هیچ
چیزی در سیستم لایسنس عوض نمی‌شود — فقط یک `if` اضافه می‌شود.

پس تصمیم امروز و فردا نیست. می‌توانید امروز رایگان منتشر کنید و فردا
قابلیت پولی اضافه کنید، بدون اینکه مشتری فعلی چیزی از دست بدهد.
