این سند مخصوص شماست، نه خریدار. هر چیزی که در محیط توسعه نتوانست
انجام شود، اینجاست — با ترتیب و با دلیل.

نسخهٔ مرجع: **۱.۱.۰** · بسته: `sparkknife-ledger.zip` (۱۰۴ فایل، ۲۲۸KB)

**وضعیت امروز:** افزونه روی PHP 8.2.33 + وردپرس ۶.۸.۳ نصب و اجرا شد.
**کل سوئیت آزمون اجرا شد: ۹۸۷ آزمون، صفر شکست، هر ۱۰ گروه.**
۱۱ متد رندر در ۸ کنترلر، ۳۱ تابع خالص، خروجی کامل، و حذف افزونه —
همه صفر Warning. ۸۹ باگ مستند و رفع‌شده.

این اولین اجرای کامل سوئیت در تاریخ پروژه است. پیش‌تر در یک نقطه
متوقف می‌شد و تصور می‌شد کد گیر می‌کند؛ اندازه‌گیری نشان داد مشکل در
بافر خروجی WebAssembly بود نه در افزونه. جزئیات در
[`AUDIT.md`](AUDIT.md) بخش «حل معمای گیر کردن سوئیت».

آنچه مانده فقط چیزهایی است که به محیط شما نیاز دارد: MySQL واقعی،
هاست واقعی، و کلید امضای شما.

## ۰. پیش از هر کاری: جفت کلید

**این تنها چیزی است که بین شما و فروش ایستاده.**

کلید خصوصی لایسنس در محیط توسعه نیست (با بازنشانی پاک شد). بدون آن:

- نمی‌توانید لایسنس صادر کنید
- بستهٔ امضاشده ندارید

### ساخت

```bash
cd tools/licensing

# کلید خصوصی — ۳۰۷۲ بیت
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out private_key.pem

# کلید عمومی متناظر
openssl rsa -in private_key.pem -pubout -out public_key.pem

# تأیید
openssl pkey -in private_key.pem -noout -check
```

### جایگزینی در کد

کلید عمومی تازه را در `sparkknife-ledger/includes/Core/class-sparkknife-ledger-license.php`
جایگزین `PUBLIC_KEY` کنید:

```php
const PUBLIC_KEY = '-----BEGIN PUBLIC KEY-----
... محتوای public_key.pem ...
-----END PUBLIC KEY-----';
```

**هر دو با هم.** اگر فقط امضا کنید و کلید داخل کد را عوض نکنید، هیچ
لایسنسی کار نمی‌کند و صفحهٔ سلامت خطا می‌دهد.

### نگهداری

| کار | چرا |
| --- | --- |
| کلید خصوصی در گاوصندوق رمز (1Password / Bitwarden) | گم شدنش همهٔ لایسنس‌ها را باطل می‌کند |
| یک نسخهٔ پشتیبان جدا از لپ‌تاپ | دیسک می‌میرد |
| نسخهٔ آفلاین روی USB | دسترسی به گاوصندوق هم از دست می‌رود |

`private_key.pem` در `.gitignore` است. این یعنی «در گیت نیست»، نه «در
جای امن است».

## ۰٫۵ اجرای سوئیت آزمون روی سایت خودتان

**این کار را بکنید، حتی اگر هیچ کار دیگری نکنید.** ۹۸۷ آزمون در
حدود یک تا دو دقیقه روی هاست شما همه‌چیز را می‌سنجد.

```bash
php tests/run-tests.php /path/to/wp-load.php
```

یا با متغیر محیطی:

```bash
SPARKKNIFE_LEDGER_TEST_WP=/path/to/wp-load.php php tests/run-tests.php
```

### چه انتظاری داشته باشید

```
▶ ۱) نصب و ساختار دیتابیس
  ✔ ...
...
────────────────────────────────────────────────────────────
همه تست‌ها موفق: ۹۸۷ مورد
```

### ⚠️ سه هشدار مهم

**۱) روی سایت تولیدی اجرا نکنید.** آزمون اشخاص و تراکنش می‌سازد و
پاک می‌کند، ولی روی دادهٔ واقعی ریسک نکنید. یک سایت آزمایشی بسازید.

**۲) اگر `STDERR` خطا داد** یعنی نسخهٔ قدیمی `run-tests.php` دارید.
این باگ در ۱.۱.۰ رفع شده. مطمئن شوید فایل‌ها از بستهٔ تازه‌اند.

**۳) اگر روی PHP 8.3+ اجرا کردید** و Warning دیدید، بفرستید. آزمون
با `E_ALL` اجرا می‌شود و هر Warning را نشان می‌دهد.

### اگر آزمون شکست خورد

خروجی کامل را نگه دارید. خط `✘` نام آزمون و مقدار واقعی را می‌گوید:

```
✘ باگ ۸۵: ارتقای بدون تغییر اسکیما نسخهٔ افزونه را به‌روز می‌کند → 0.0.1
```

شمارهٔ باگ را در [`AUDIT.md`](AUDIT.md) جستجو کنید — توضیح کامل
علت و رفعش آن‌جاست.

## ۱. آزمون روی سایت خودتان

محیط توسعه فقط SQLite داشت. شما باید با MySQL واقعی تست کنید.

### قبلش

- [ ] یک **سایت آزمایشی** یا نسخهٔ کامل پشتیبان از سایت فعلی
- [ ] HTTPS فعال
- [ ] PHP 7.4 یا بالاتر (پیشنهاد: ۸.۱+)

### مراحل

**۱) نصب**

پیشخوان → افزونه‌ها → افزودن → بارگذاری افزونه →
`sparkknife-ledger.zip` → نصب → فعال‌سازی

**۲) بررسی اولیه**

بعد از فعال‌سازی باید ببینید:

- منوی «دفتر حساب» در نوار کناری
- ویزارد راه‌اندازی چهارمرحله‌ای
- پیام «افزونه با موفقیت نصب شد»

اگر منو نیست → `docs/INSTALLATION.md` بخش «منو ظاهر نمی‌شود».

**۳) صفحهٔ سلامت**

دفتر حساب → سلامت و امنیت

انتظار: ۷ بررسی. دو مورد ممکن است `warn` باشند:

| بررسی | چرا warn |
| --- | --- |
| HTTPS | اگر سایت روی HTTP باشد — **این را رفع کنید** |
| پیشوند جدول | اگر `wp_` باشد — بی‌خطر |
| لایسنس | `info` تا کلیدی وارد نشود |

**۴) آزمون عملکرد**

| # | کار | انتظار |
| --- | --- | --- |
| ۱ | یک شخص بسازید | در فهرست دیده شود |

| ۳ | تراکنش خروجی ثبت کنید | مانده کم شود |
| ۴ | تراکنش را ابطال کنید (با دلیل) | از جمع خارج شود، در تاریخچه بماند |
| ۵ | بازیابی کنید | دقیقاً به حالت قبل برگردد |
| ۶ | شخص را حذف کنید | از فهرست برود، تراکنش‌هایش بمانند |
| ۷ | بازیابی شخص | برگردد با همان مانده |

این مهم است — باگ ۸۶ از همین‌جا پیدا شد:

## ۳. امضای بسته

بعد از ساخت کلید و تست موفق:

```bash
# بسته را بسازید
zip -r sparkknife-ledger.zip sparkknife-ledger \
  -x '*.DS_Store' -x '__MACOSX/*' -x '*/node_modules/*' -x '*.pem'

# امضا
./tools/sign-release.sh sparkknife-ledger.zip

# بررسی پیش از انتشار — همیشه
./tools/verify-release.sh sparkknife-ledger.zip
```

انتظار:

```text
✓ چکسام SHA-256 مطابق است
✓ امضای RSA معتبر است
نتیجه: بسته معتبر است ✓
```

سپس هر سه فایل را با هم منتشر کنید: `.zip`، `.sha256`، `.sig`.

## آنچه در محیط توسعه انجام نشد

صادقانه، تا بدانید چه چیزی تست‌نشده مانده:

| مورد | چرا |
| --- | --- |
| MySQL واقعی | محیط توسعه فقط SQLite داشت (وردپرس ۶.۸.۳ + درایور SQLite) |
| نصب روی هاست | نیاز به سایت واقعی دارد |
| امضای بسته | کلید خصوصی موجود نیست |
| اسکرین‌شات محصول | محیط توسعه پریویو ندارد |

**آنچه در این پاس اجرا شد:** PHP-WASM درست شد (مشکل API بود نه محیط)
و افزونه روی **PHP 8.2.33 + وردپرس ۶.۸.۳** واقعاً نصب و فعال شد.
۲۶ assertion تازه (باگ ۸۶ و ۸۷) و رفع باگ ۸۸ روی همین محیط آزموده
شدند — `Undefined property` واقعاً دیده شد و پس از رفع، صفر Warning.

**آنچه هنوز اجرا نشده:** سوئیت کامل در WASM به‌خاطر کندی بیش از حد
در بخش `Settings::save()` (بلوک باگ ۸۴/۸۵) کامل نشد. ۹۵۷ assertion
اجرا شد، همه سبز. اگر مؤلفه‌ای از ۳۱ assertion باقی‌مانده با محیط
واقعی نمی‌خواند، اولین اجرای `tests/run-tests.php` روی سایت شما
نشانش می‌دهد.
