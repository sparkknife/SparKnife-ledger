# ابزار لایسنس

این پوشه در بستهٔ فروش **نیست**. فقط برای صدور کلید لایسنس است و باید
روی دستگاه خودتان بماند.

## ⚠️ مهم‌ترین نکته

**`private_key.pem` را گم نکنید.**

کلید عمومی داخل `includes/Core/class-sparkknife-ledger-license.php`
embed شده است. هر لایسنسی که صادر می‌کنید با کلید خصوصی امضا می‌شود.

اگر کلید خصوصی گم شود:

- هیچ لایسنسی با کلید عمومی موجود جور نمی‌شود
- **همهٔ مشتریان فعلی باطل می‌شوند**
- برای ادامه باید جفت کلید تازه بسازید، کلید عمومی را در کد عوض کنید،
  نسخهٔ تازه منتشر کنید و برای همهٔ مشتریان کلید جدید صادر کنید

این اتفاق یک بار در پاس ۱۱ افتاد (باگ ۷۹ در `docs/AUDIT.md`): کلید
خصوصی فقط روی دیسک بود، محیط بازنشانی شد، و محصول عملاً قابل فروش
نماند — بدون اینکه هیچ تستی شکست بخورد.

### پس چه کنید

کلید خصوصی را در **گاوصندوق رمز** بگذارید، نه فقط روی دیسک:

- 1Password / Bitwarden / KeePassXC (فایل را در آیتم امن ذخیره کنید)
- یا رسانهٔ آفلاین (USB در گاوصندوق)
- و یک نسخهٔ پشتیبان جدا از لپ‌تاپ کاری

فایل `private_key.pem` در `.gitignore` است و **نباید** کامیت شود. این
درست است — ولی gitignore یعنی «در گیت نیست»، نه «در جای امن است».

## ساخت جفت کلید تازه

فقط وقتی لازم است که کلید قبلی گم شده باشد:

```bash
cd tools/licensing
openssl genrsa -out private_key.pem 2048
openssl rsa -in private_key.pem -pubout -out public_key.pem
chmod 600 private_key.pem

# صحت جفت را بررسی کنید
echo test > /tmp/v.txt
openssl dgst -sha256 -sign private_key.pem -out /tmp/v.sig /tmp/v.txt
openssl dgst -sha256 -verify public_key.pem -signature /tmp/v.sig /tmp/v.txt
# باید چاپ کند: Verified OK
```

سپس **محتوای `public_key.pem` را در ثابت `PUBLIC_KEY`** در
`includes/Core/class-sparkknife-ledger-license.php` جایگزین کنید.

> `openssl_pkey_new()` داخل PHP کار نمی‌کند (در PHP-WASM خطا می‌دهد و
> روی برخی هاست‌ها هم محدود است). از دستور `openssl` سیستم استفاده
> کنید.

## صدور کلید برای مشتری

```bash
php tools/licensing/issue.php \
  --domain=example.com \
  --edition=pro \
  --expiry=2027-12-31 \
  --serial=CUST-001
```

| گزینه | توضیح |
| --- | --- |
| `--domain` | دامنهٔ مشتری. `*` برای هر دامنه، `*.example.com` برای زیردامنه‌ها |
| `--edition` | `pro` یا `agency` |
| `--expiry` | تاریخ میلادی `YYYY-MM-DD`، یا خالی برای لایسنس دائمی |
| `--serial` | شمارهٔ سفارش شما، برای پیگیری |
| `--verify` | فقط یک کلید موجود را بررسی کن، کلید تازه صادر نکن |

ابزار پس از امضا خودش کلید را بررسی می‌کند و اگر معتبر نبود، هشدار
می‌دهد.

### بررسی یک کلید

```bash
php tools/licensing/issue.php --verify="SPK1.xxxxx.yyyyy"
```

## شکل کلید

```
SPK1.<payload به base64url>.<امضای RSA-SHA256 به base64url>
```

payload خام: `domain|expiry|edition|serial`

چون payload امضا شده، تغییر هر حرفی امضا را باطل می‌کند.

## نکته‌های فروش

**کلید را برای دامنهٔ درست صادر کنید.** مشتری که برای `example.com`
خریده، روی `www.example.com` هم کار می‌کند، ولی روی `example.org`
نه. اگر مشتری دامنه‌اش را عوض کرد، کلید تازه صادر کنید.

**لایسنس دائمی با `--expiry=` خالی صادر می‌شود.** اگر می‌خواهید
تمدید سالانه بفروشید، تاریخ بگذارید.

**شمارهٔ سریال را در سیستم سفارش‌هایتان ثبت کنید.** وقتی مشتری زنگ
می‌زند، `--verify` تنها می‌گوید کلید معتبر است یا نه، نه اینکه برای
چه کسی صادر شده.
